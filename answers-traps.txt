1.Which registers contain arguments to functions? For example, which register holds 13 in main's call to printf? 
-> In RISC-V architecture, the registers a0 through a7 are used to pass integer arguments to functions. 
For example: register a2 holds the value 13, register a1 holds the value 12, register a0 holds the address of the string "%d %d\n".

2.Where is the call to function f in the assembly code for main? Where is the call to g? (Hint: the compiler may inline functions.) 
-> There are no calls to f or g in the assembly code for main. 
Inside f, the compiler inlined g. At instruction 0x14, instead of calling g, f simply executes addiw a0,a0,3 (which is the logic copied from g).
In main, the compiler inlined everything. It calculated the result of f(8) + 1 (which is 12) at compile time and placed the final value directly into register a1 at instruction 0x26
    ```
    26: 45b1    li a1,12
    ```

3.At what address is the function printf located? 
-> 
    ```
    30:	00000097          	auipc	ra,0x0 //(1)
    34:	600080e7          	jalr	1536(ra) # 630 <printf> //(2)
    ```
Line (1) set register ra to the current PC: 0x30
Line (2) jumps to (ra + 1536)
The address is: 0x30 + 1536 = 0x30 + 0x600 = 0x630


4.What value is in the register ra just after the jalr to printf in main?
->  
    ```
    34:	600080e7          	jalr	1536(ra) # 630 <printf>
    exit(0);
    38:	4501                li	a0,0
    ```
The value in the register is 0x38
The jalr instruction jumps to the function printf but simultaneously saves the address of the next instruction (PC + 4) into ra so the program know where to return later: 0x34 + 4 = 0x38


5.Run the following code. 
    ```
    unsigned int i = 0x00646c72; 
    printf("H%x Wo%s", 57616, (char *) &i); 
    ```
What is the output? (Here's an ASCII table that maps bytes to characters.)
The output depends on that fact that the RISC-V is little-endian. 
If the RISC-V were instead big-endian what would you set i to in order to yield the same output? 
Would you need to change 57616 to a different value? 
-> The output is "HE110 World". 
'%x' tells the printf to take the decimal value 57616 and convert it into hexadecimal (571616(10) = E110(16))
'%s' relies on little-endian architecture RISC-V (like x86) stores the rightmost part of the hex number at the lowest memory address.  
    ```
    +0 - 0x72 - 'r'
    +1 - 0x6c - 'l'
    +2 - 0x64 - 'd'
    +3 - 0x00 - '\0'
    ```
If the RISC-V were big-endian, I would set i to 0x726c6400. This is because big-endian stores the the leftmost part of the hex number at the lowest memory address.
We do not need to change 57616. Endianness only determines how a value is stored in memory; it does not change the mathematical value of the number itself.

6.In the following code, what is going to be printed after 'y='? (note: the answer is not a specific value.) Why does this happen? 
    ```
    printf("x=%d y=%d", 3);
    ```
-> The value of y is a random garbage value. 
The printf function expects the format string in register a0 and the value 3 in register a1.
The value of x is corresponding to register a1, and the value of y is corresponding to register a2.
Since the code does not provide a value for y, register a2 is never set, so printf simply prints the uninitialized leftover data found in that register.
